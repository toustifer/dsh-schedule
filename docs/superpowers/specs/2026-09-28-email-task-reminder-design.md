# 邮件任务提醒 · 设计文档

- **日期**：2026-09-28
- **状态**：待 YG 审阅
- **范围**：dsh-schedule 插件新增「日程开始前邮件提醒」能力

---

## 1. 背景与目标

插件目前只有**被动展示**：日程躺在右侧栏面板里，必须主动打开才看得到。YG 的实际痛点是有任务滚动多天无人察觉——曾有一条「思若宁 AI 补贴登记」连续顺延了 12 天。

本次新增**主动提醒**：日程开始前 10 分钟，通过邮件 + 面板提示把人拉回来。

## 2. 需求（已与 YG 确认）

| 项 | 决定 |
| :--- | :--- |
| 触发时机 | 日程开始前 **10 分钟** |
| 提醒范围 | **仅带具体时间的日程**（无时间的待办不触发） |
| 收件人 | 多个邮箱，**同一封都发一遍** |
| 通道 | 邮件 + DSH 面板内提示 |
| 发信方式 | **QQ 邮箱 SMTP**（方案 A），适配器可替换 |

## 3. 非目标（YAGNI）

以下均已明确排除，不实现：

- 微信 / Telegram / 企业微信 / 第三方推送
- 每日早间汇总、每周复盘
- 逾期告警
- 无时间任务的提醒
- 富文本 / HTML 邮件（纯文本足够）

## 4. 架构

### 4.1 三个单元

**调度器**（host 端，`src/notify/scheduler.js`）
职责：每分钟跑一次，算出「该发哪些提醒」。
输入：日程数据 + notify 配置 + 当前时间。
输出：一组待发提醒。
**不负责发信**——纯函数化便于单测。

**发信适配器**（host 端，`src/notify/transports/`）
统一接口：`send({ recipients, subject, text }) → Promise<void>`
实现三种：`smtp`（nodemailer，默认）、`cfmail`（HTTP，指向 mail.stifer.xyz）、`webhook`（任意 HTTP 端点）。
由配置里的 `transport.kind` 决定用哪个。

**提醒状态**（host 端，复用插件扩展字段）
去重键：`${itemId}@${发生时刻}`
存储：扩展字段 `notify.sentLog`

### 4.2 数据流

```
每分钟触发：
  now    = 当前时间
  window = [now, now + leadMinutes]
  rows     = 所有日程在 window 内、且带具体时间的发生
  pending  = rows 中「去重键不在 sentLog」的那些
  if 配置启用 且 pending 非空:
      send(recipients, 主题, 正文)
      成功后写 sentLog
      通知客户端高亮
```

## 5. 关键设计决策

### 5.1 去重键必须包含「发生时刻」

只用 `itemId` 会让**每周重复的课程只提醒一次**。
用 `${itemId}@${YYYY-MM-DDTHH:MM}` 可以保证：

- 同一门课每周都提醒
- 改了时间会重新提醒（时刻变了 → 键变了）
- 调度器重复运行不会重复发

### 5.2 配置存扩展字段，不新建文件

插件已有 `dailytask_doc_patch` 通道，且 0.4.0 修过「未知顶层字段在 load 时被丢弃」的 bug，现在以原文为基底保留未知字段。因此新增 `notify` 字段安全，**不需要改数据格式版本**。

### 5.3 发信失败不阻塞

每个收件人独立 try/catch：失败记日志、**不写 sentLog**，不因为一个收件人失败影响其他收件人。

### 5.4 默认关闭

`enabled` 默认 `false`。必须显式开启，避免配置还没填好就开始乱发。

## 6. 边界与限制

### 6.1 已知限制（必须告知）

**插件活在 DSH 进程内。DSH 未运行、机器关机 → 不会有任何提醒。**
这是架构约束，不是缺陷。它不是手机闹钟，是「DSH 运行期间的提醒」。

### 6.2 边界情况处理

| 情况 | 行为 |
| :--- | :--- |
| 日程开始时刻已过（不在窗口内） | 不提醒 |
| 同一条日程同一时刻多次命中 | 去重键挡住 |
| 授权码错误 / SMTP 不可达 | 记日志，不写 sentLog |
| 收件人列表为空 | 跳过发信，只做面板提醒 |
| 机器休眠跨过提醒时刻 | 唤醒后窗口已过 → **不补发**（避免开机轰炸） |
| 同时段多条日程即将开始 | 合并成一封邮件发送，减少打扰 |

## 7. UI

- **面板高亮**：右侧栏日程面板里，10 分钟内即将开始的条目加高亮样式
- **顶栏角标**：复用现有 badge 机制，不新建

## 8. 配置结构

```json
{
  "notify": {
    "enabled": false,
    "leadMinutes": 10,
    "recipients": ["1577574695@qq.com"],
    "transport": {
      "kind": "smtp",
      "host": "smtp.qq.com",
      "port": 465,
      "secure": true,
      "user": "1577574695@qq.com",
      "pass": "<QQ 邮箱授权码>"
    },
    "sentLog": {}
  }
}
```

## 9. 测试策略

- **调度器纯函数单测**：给定数据 + 时间 → 断言提醒列表
- **去重单测**：同一时刻重复调用只产生一条
- **跨周单测**：同一 itemId 在不同日期产生不同去重键
- **适配器**：用 mock transport，**不发真邮件**
- **端到端**：造一条「1 分钟后开始」的日程，手动触发调度器验证

## 11. 安全说明

QQ 邮箱授权码属于敏感凭据，将写入插件扩展字段（本地数据文件 `~/.dsh/dsh-schedule-data.json`）。
该文件仅本机可读；授权码不会出现在任何邮件内容或日志里。
